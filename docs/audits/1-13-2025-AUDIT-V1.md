## Executive Summary

The implementation plan is strong on structure (sprint decomposition, acceptance criteria, testing strategy) but has several **documentation-level inconsistencies** that would lead to incorrect or non-portable implementations if followed verbatim:

1. **Money correctness footguns:** multiple specs use floating point (`Double`/`Float`) in money construction and proportional allocations, contradicting the “no floating point for money” principle and creating rounding/consistency risk.
2. **KMP portability footguns:** several “`commonMain`” code examples use JVM-only APIs (`java.io.File`, `java.security.*`, `java.text.*`, `java.net.*`), but the project setup currently defines only `commonMain/androidMain/desktopMain` without an intermediate JVM source set or `expect/actual` boundaries.
3. **Untrusted input hardening gaps:** PDF parsing “sandboxing”, model bundle verification, and user regex rules need tighter constraints to avoid DoS, path traversal, or integrity bypass edge cases.

This audit documents the issues and applies fixes directly to the architecture and implementation-plan documents. The checklist below tracks changes.

## Applied Fixes (What Changed)

- `docs/PRDs/13-architecture-decision-records.md`: ADR-006 now treats `minorUnits` as canonical and moves parsing/formatting out of the Money core; avoids `Double` for construction/parsing.
- `docs/implementation-plan/00-project-foundation/01-kmp-project-setup.md`: adds `jvmMain` source set and makes `androidMain`/`desktopMain` depend on it to correctly place JVM-only implementations.
- `docs/implementation-plan/01-core-data-layer/03-money-type.md`: removes `Double` constructors/multipliers, adds basis-points multiplication, adds `MoneyParser`/`MoneyFormatter`/`MoneyLocaleFormatter`, and updates allocator APIs to integer-only allocation.
- `docs/implementation-plan/01-core-data-layer/05-csv-import-pipeline.md`: amount parsing now uses integer minor-unit parsing; currency is supplied via `CsvParseOptions.currencyCode`.
- `docs/implementation-plan/03-receipt-splitting/05-tax-fee-allocation.md`: proportional allocation now uses integer weights via `MoneyAllocator.splitByWeights`; tax calculation uses basis points.
- `docs/implementation-plan/02-categorization-engine/02-ml-categorization.md`: amount bucketing no longer requires `toMajorUnits()`; model bundle manager includes size/path constraints and canonical-signature guidance.
- `docs/implementation-plan/02-categorization-engine/05-rules-engine.md`: regex rules are routed through `SafeRegex` to avoid regex DoS; amount range rules parse major-unit decimals deterministically.
- `docs/implementation-plan/**`: replaced `formatUsd()` examples with `formatForDisplay()` to match the new formatting boundary.
